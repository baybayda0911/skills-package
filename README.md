# Skills Package

一套持续积累的个人 AI 技能集合，旨在改善 AI 的思考过程、提高工作效率，并帮助它输出更清晰、可靠、可执行的结果。

这里的技能（Skill）是一份可重复使用的工作说明：告诉 AI 何时使用、怎样推进任务、需要检查什么，以及何时停止。它不是模型本身，也不是独立运行的应用程序。

## 仓库用途

- 把有效的提问方法、思考步骤和输出要求整理成可复用技能，减少每次重新编写提示词的工作。
- 集中维护技能正文、参考材料和模板，让改进有记录、文件容易查找。
- 按任务选择需要的技能，而不是让所有规则同时参与每一次工作。
- 尽量减少对特定项目和本机环境的依赖，便于迁移到其他项目或支持技能的 AI 工具。

仓库不限于某个技能或某类项目。后续可以加入规划、研究、写作、开发、检查和日常工作等方向的技能；这些是扩展方向，不代表目前均已提供。

## 技能清单

| 技能 | 用途 | 使用说明 |
| --- | --- | --- |
| `idea-refiner` | 澄清关键选择、挑战假设并收敛为可审阅方案或小规模验证计划 | [技能入口](skills/idea-refiner/SKILL.md) |
| `ten-step-learning` | 建立任务驱动的专业学习路径，支持研究规划与持续训练，以及诊断、示范、练习、反馈和延迟复验、进度索引、三级检验与通过线（v2.5.2） | [技能入口](skills/ten-step-learning/SKILL.md) |

每个技能的适用条件、工作流程和模板都保存在自己的目录中。根目录 README 只介绍整个仓库及通用使用方式。
`idea-refiner` 的记录交接、领域补充与对照演练方法按需加载；普通讨论不需要完整模板或评测流程。
`ten-step-learning` 先给目标、诊断状态、骨架和示范练习样品，确认后展开研究手册或当前单元训练。测试、解释和复习穿插全程；资料生成不代表用户已掌握。详见[使用说明](skills/ten-step-learning/README.md)。

## 快速使用

### 1. 获取仓库

在你希望保存仓库的父目录运行：

```bash
git clone https://github.com/baybayda0911/skills-package.git
```

已有本地副本时直接使用，不需要重复克隆。下载或克隆文件不等于安装技能。

### 2. 选择并加载技能

先从技能清单找到合适的条目，阅读对应 `SKILL.md` 中的适用条件。

- 工具支持本地技能安装时，将选中的 `skills/<skill-name>/` 整个目录安装到该工具要求的位置，保留其中的相对路径。
- 工具能读本地文件但不支持技能安装时，明确请它读取对应 `SKILL.md`，再按正文要求读取有关参考材料。
- 工具不能读本地文件时，需要提供技能正文及任务所需的参考材料；仅提供文件路径不会让它获得文件内容。

不同工具的安装目录、加载方式和调用语法可能不同，请以对应工具说明为准。本仓库目前不提供一键安装器，也未验证跨工具自动发现。

### 3. 提供具体任务

支持 `$技能名` 调用的环境，可以使用下面的形式：

```text
请使用 $idea-refiner 完善我的构思：……
本次只讨论并形成方案，不开始实施。
```

需要系统学习一个陌生领域时：

```text
请使用 $ten-step-learning 按十步法带我学：……
我目前零基础，想独立完成的任务是：……
采用持续训练；每周可投入……小时，先给骨架和示范练习。
```

该技能按需集中补齐用途、目标任务、起点、预算和资源。骨架提供新十步导航、第4步完整示范与第5步短练习；研究模式的学习成绩保持未观察，训练模式依据实际作答和产物推进。需要只研究领域时，可明确说“采用研究与规划模式”。

在已安装且支持技能发现的助手中，也可以直接说“使用完善构思技能”或“使用 idea refiner”，再说明你的想法；两者均指 `idea-refiner`，不改变规范技能标识。

不支持上述调用方式、但能读取文件的助手，可以这样使用：

```text
请读取 skills/idea-refiner/SKILL.md 和其中与任务有关的参考材料，
按该技能说明帮助我完成下面的任务：……
```

第二个示例的路径相对于仓库根目录；在其他工作目录中使用时，应提供实际可访问的文件位置。

描述任务时尽量说明目标、现有材料、主要限制和期望交付物。使用技能不等于授权购买、对外发送、删除、安装或发布等行动。

## 文件组织

根目录保存仓库级说明与规则，`skills/` 保存各个技能：

- [README.md](README.md)：仓库用途、使用方式和技能清单。
- [AGENTS.md](AGENTS.md)：维护本仓库时的协作约定。
- [.gitignore](.gitignore)：本机配置和临时文件的忽略规则。
- [LICENSE](LICENSE)：仓库许可证。
- `skills/<skill-name>/`：一个技能对应一个独立目录。

技能目录采用以下约定，只有 `SKILL.md` 必需，其余按实际需要添加：

| 文件或目录 | 作用 |
| --- | --- |
| `SKILL.md` | 技能入口，包含名称、适用条件和工作步骤 |
| `references/` | 按需读取的补充说明或模板 |
| `scripts/` | 技能需要的可执行辅助脚本 |
| `assets/` | 可直接使用或复制的素材 |
| `agents/` | 特定工具支持的展示或配置文件 |

`scripts/`、`assets/` 等是可选约定，不表示每个现有技能都包含它们。仓库源码目录也不是工具的自动安装目录。

## 添加与维护

1. 在 `skills/` 下创建技能目录，使用小写英文、数字和单连字符命名。
2. 编写 `SKILL.md`，保持其中的 `name` 与目录名一致，明确适用条件和不适用情况。
3. 按需添加参考材料、模板或脚本，避免复制无关规则和私人资料。
4. 检查格式、相对引用和使用示例，再用真实任务或脱敏场景验证效果。
5. 更新根目录技能清单，保留第三方来源与适用的版权声明。

维护前先阅读 [协作约定](AGENTS.md)。文件格式正确不代表实际任务效果已验证，验证结论应区分结构检查、对话演练和真实运行。

## 限制与安全

- 技能效果取决于模型能力、上下文和可用工具，不保证每次都得到相同结果。
- `idea-refiner` 已于 2026-10-12 完成一次六场景、34 条助手回复的独立代理多轮脚本对照演练，并在局部修改后完成票据场景的三条回复复测与一条最终草案固定回放检查。各阶段分别记录，未将局部结果当作全套新版重跑；尚未完成重复模型比较、真实业务效果、全局安装或跨工具兼容验证。单次演练不代表普遍优于其他技能，也不代表安装或运行已通过。
- `ten-step-learning` v2.0依据教学设计评审重排十步并补齐学习循环；结构检查、独立代理演练与真人学习验证分别记录。改版的学习效果及跨工具真实运行仍待验证。仓库标签`v1.1`保留改版前完整技能，`v2.0`保留改版成果，供后续同条件对照。
- `ten-step-learning` v2.1是 v2.0 的单点补丁，只新增一条记账规则（骨架示范基于假设起点时须标注，并不得计入"已讲解"或任何能力证据）。触发它的是一次**真实学习会话**中观察到的事实：示范已印出正确算式而学习者仍在同批诊断中答错。该观察只说明一个领域的单次会话，**不足以证明学习效果**；v2.1 未改变十步顺序、模式与评价口径，故不与 v2.0 构成需重新对照的版本差异。
- `ten-step-learning` v2.2是另一条单点补丁，补**交付顺序**：第 3 步最小领域地图必须先于第 4 步示范与第 5 步练习交付，骨架模板相应新增第 3 步区块。触发它的是学习者的直接反馈——第 1、2、4、5 步都执行了但第 3 步被跳过，学习者因此感到"知识点零散、不成体系"。该判断属**可用性事实**（地图缺失会被学习者直接感知），但同样只来自单一领域、单次会话，**不构成学习效果的证据**；v2.2 与 v2.1 之间亦不需重新做对照实验。
- `ten-step-learning` v2.3补**教考配比、通过线、失败回溯与第 3 步讲法**：教∶考比例按知识点层级分层（初阶 8∶2、中阶 6∶4、高阶 5∶5）；一个知识点记"掌握"须同时满足"能讲清机制"与"能独立做对"；未通过时回溯到最早出现漏洞的先修层补课；第 3 步改为"先整体串框架 → 再按层讲含义与用途 → 每层末回顾＋概念小测"；并禁止跳过第5步的"跟做""补全"两级。触发它的是学习者的第二轮反馈——该会话 9 次任务全部为无提示独立作答、教学材料仅 2 份，**教∶考约 2∶9**，教学被降级成测验。**分层比例是可调整的默认值，来自使用体验判断而非学习科学实验**，故 v2.3 同样不足以宣称学习效果改善，与 v2.2 之间也不需重新做对照实验。
- `ten-step-learning` v2.4补**示范的质量下限**：示范里每个系数、指数、分母、常数都必须解释来源，并写明近似条件与略去项、附自查问题——**"可复现"才是示范的验收条件，"答案正确"不是**。触发它的是学习者的直接反馈：示范中的 `½ × Γ × (ΔS)²` 只给了算式与结果，学习者看得懂 Γ 与位移却看不懂 ½ 和平方的来源。该反馈同样只来自单次会话，故 v2.4 亦不构成学习效果结论。
- `ten-step-learning` v2.5补**进度索引与里程碑**：新增三级索引（大板块＝里程碑／中单元＝一级节点／小节＝二级节点）、四档状态（未开始／已输入／已练／已通过，可并列"待复验"）、进度总览条（进度文件顶部＋每轮回复末尾一行）、节点仅在全部小节通过时点亮、里程碑只作事实陈述（禁等级/徽章/打卡），并要求第 3 步地图同时是"索引课程表"、与进度表共用一套编号。触发它的是学习者的直接反馈：教材天然带"单元→大节→小节"层级，而本技能没有进度标记，导致"学了一天也不知道自己处于什么进度"，也无法立里程碑获得驱动力；并明确要求**里程碑再细分一级**，以免"过很久才完成一个、没有成就感"。**这与 v2.0 取消覆盖率百分比不矛盾**——v2.0 的取消是对的，但未补上替代的可感知表征，v2.5 补的是这个缺口；它报的是计数与坐标，不是完成度百分比。该补丁同样来自单一领域、单次会话的使用体验判断，**不足以宣称学习效果改善**，与 v2.4 之间不需重新做对照实验。
- `ten-step-learning` v2.5.1（**补丁级**，按该技能 `references/设计规范.md` §0 的版本编号约定：不改结构、旧产出不需重新对照，故记为 `x.y.z` 补丁）给索引**补上配套的三级检验**，并补一条**推进顺序**规则：每个**小节**末尾有课后练习（第 5 步，允许提示，是"已练"状态的唯一来源）、每个**中单元**结束有单元小测（第 6 步，不给提示，覆盖该单元全部小节）、每个**大板块**结束有里程碑综合测试（第 8 步，五类题型至少覆盖 4 类、计算＋应用合计 ≥40%）；检验结果写入进度文件的**检验台账**（只有入台账的检验才算做过）。同时规定**推进顺序＝索引顺序**，跨板跳跃必须留痕并出"欠账清单"，否则索引图会退化成"每个板块都亮一点、却没有一条完整路径"。触发它的是同一次会话的追加反馈：① 学习者要求三级检验；② 学习者发现索引图呈 B1–B4 散点点亮、追问"这是学习计划特意安排的吗"——实为该会话早段由错误驱动而非地图驱动所致。**一条关键辨析**：课后练习属引导练习、允许提示，因此**不破坏** v2.3 的分层教∶考配比（8∶2／6∶4／5∶5）；若当作测验使用则配比会被推向 5∶5。题型比例与每小节题量均为**可调整默认值**，来自使用体验判断，**不足以宣称学习效果改善**，与 v2.5 之间不需重新做对照实验。
- `ten-step-learning` v2.5.2（**补丁级**）给三级检验补上**通过分数线**：课后练习 **≥90%**、单元小测 **≥80%**、里程碑综合测试 **≥75%**（练习允许提示，小测与综合测试不给提示）；**含关键错误一律不通过**，不论总分。并修掉一个**会让分数线失效的口径缺陷**——v2.5.1 规定每小节课后练习 1~3 题，若按题数算 90% 则实际退化成"必须全对"（3 题时 2/3 不合格、只有 3/3 达标），中间没有档位；因此改为**按判分点计**，并要求**小节练习的判分点总数不少于 5 点**。同时把该技能的**版本编号约定扩为三级**：大版本（改整体结构、框架或逻辑）／小版本（新增独立功能或模块）／补丁（在既有机制内新增或修正规则、字段、表述），判定自上而下、命中即止。触发它的是同一次会话的追加反馈：学习者同意"练习有提示、小测与综合测试无提示"，并给出三条通过线；同时要求"新增功能纳入小版本、改结构框架逻辑纳入大版本"。上述缺陷非用户提出，系应用规则时发现。三条分数线均为**可调整默认值**，**不足以宣称学习效果改善**。
