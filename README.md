# Skills Package

个人技能集合仓库，保存可复用的技能源码、按需说明和模板。每个技能独立存放，方便以后添加新技能或选择性安装。

本仓库是源码集合，不是某个工具的自动安装目录。保存文件、安装技能、本地版本管理和上传 GitHub 是不同操作。

## 现有技能

| 技能 | 用途 | 入口 |
| --- | --- | --- |
| `idea-refiner` | 把模糊构思完善为清晰、可执行、可验证的方案 | [SKILL.md](skills/idea-refiner/SKILL.md) |

`idea-refiner` 为初版。它保留原 `refine-idea` 的分轮澄清、按前提追问、确认记录及证据交付方法，移除了固定项目目录与专属领域要求；不覆盖原技能。

支持产品、软件、自动化、内容、研究、活动及个人工作的方案梳理。它是通用思考流程，不代替各行业的专业知识和复核。

## 使用

在支持本地技能的工具中，将 `skills/idea-refiner/` 整个目录放入该工具要求的技能位置，保留模板和相对路径。不同工具的安装目录和调用方式可能不同，应遵守对应工具说明。

本次未执行安装，也未验证任何工具的自动发现。`agents/openai.yaml` 是支持该格式的工具可用的展示配置，不是独立运行程序。

支持 `$技能名` 调用的环境可以这样开始：

```text
请使用 $idea-refiner 完善我的想法：我想组织一次读书交流活动，
但只有两周准备时间。先帮我明确最小可行方案，不开始执行。
```

没有技能加载能力、但能读取本地文件的助手，也可以明确要求它读取入口及适用模板后开展讨论。没有文件读取能力时，需另行提供技能正文。

技能通常按下面的方式推进：

1. 沿用已有想法，整理目标、对象和本轮范围。
2. 每轮问少量关键选择，给 A/B 选项和推荐。
3. 输出方案，明确做与不做、未知项和完成标准。
4. 只要方案就交付后停止；同时获得确认与实施授权时才落地。

简单构思在对话中收敛，不强制建文件。较复杂议题使用通用模板，并只加载相关场景补充。

## 验证情况

已在本地使用 Python 与 PyYAML 完成静态检查：

- 入口的说明格式可解析，名称与目录一致，描述含适用及排除条件。
- 入口正文少于 500 行，5 个模板引用均存在。
- 展示配置可解析，默认提示引用 `$idea-refiner`。
- 新增文件不含写死的盘符路径或原项目专属标识。
- 10 项关键行为规则存在，包括方案停止点、未知项、确认、授权和隐私。

以上只证明文件结构与规则覆盖，不证明模型实际遵循规则。未进行安装、独立模型多轮演练、跨工具兼容验证或 GitHub 发布。

后续实际演练建议：

| 场景 | 应重点观察 |
| --- | --- |
| 校园交易工具 | 先收敛最小使用流程，不默认扩成功能大全 |
| 文件备份流程 | 先明确覆盖、重复和失败处理，不擅自建立定时任务 |
| 研究报告 | 区分研究计划与实际结论，不编造证据 |
| 读书交流活动 | 关注对象、准备、现场流程和退出，不强求代码 |
| 个人学习安排 | 无项目文件也能讨论，私人记录不默认进仓库 |
| 已有方案续接 | 沿用已有确认，只重开受新信息影响的分支 |

每次演练记录实际提问、确认和停止行为，再决定是否调整规则。不要把静态检查表当作对话测试通过记录。

## 维护与边界

新增或修改技能后，检查入口格式、相对引用、使用示例和行为规则，并同步本文件中的技能清单。

私人资料、日志、缓存和本机配置留在源码之外。忽略规则不能证明历史或已跟踪文件中没有敏感内容。

本次没有初始化 Git、建立远程关系、提交、推送或安装技能。准备公开前，应另行核对来源权利、选择许可证并完成发布前检查；不默认将仓库视为已经开源。
