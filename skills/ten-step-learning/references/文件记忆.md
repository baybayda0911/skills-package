# 轻量文件记忆 · v3.2

本模块只负责发现、保存和续接，不另设掌握度算法。成绩、历史/当前与结业判定仍以[交互与状态](交互与状态.md)为准。不接入Hindsight、数据库、后台同步或模型服务。

## 1. 目录与身份：两类主文件

训练开始或跨会话续接时读本文件。沿用用户已明确的共享学习根目录；未提供时只询问一次所需位置，可先教学并给未落盘更新，不擅自选全局技能目录。只规划且不要求保存个人信息时，不建立档案。现有单课程进度仍可独立使用，未配置共享根不阻断学习。

Codex与Trae须有同一根目录的读写权限、加载兼容本模块的技能；两端调用时提供这个入口。记忆不依赖聊天历史或应用专用缓存，不承诺自动发现。示例均是用户工作目录布局，不在技能源码内实例化：

```text
<共享学习根>/
  学习者档案.md
  courses/<course-id>/学习进度.md
  courses/<course-id>/产物/…（仅确有产物时）
```

- 一个根默认一个学习者，`learner_id`为稳定别名，无需真实姓名；不同学习者分根。称呼`display_name`、改名/换人及系统介绍记录按[开课导学](开课导学.md)核对；同昵称不作身份认证。课程用稳定`course_id`，改名不改ID。
- [学习者档案模板](../assets/学习者档案模板.md)集中存课程索引、确认偏好、观察/待验证假设及变更记录。课程索引只是入口，不复制成绩；最近课程仅供建议，含糊指代或多门候选时先核对，不默认“最近”就是本次目标。
- 每课程沿用[学习进度模板](../assets/学习进度模板.md)，增加身份、记录修订和续学摘要。跨课程引用须写`learner_id/course_id/T或A或E-ID`，不同课程的T01、A01、E01不能互认或合并。
- 课程路径相对共享根；课程产物路径相对课程目录。读取前核对规范化后仍在根内；绝对路径、`..`越界或符号链接逃逸先请用户核对，不跟随陌生路径。根外旧文件导入另按§6。
- 新建稳定ID先查索引和课程头；撞名不覆盖，保留原ID并选未用ID。身份、文件头和索引不一致时暂停该记录写入，核对目标；不得把别人的数据合并。

## 2. 每次续学只读取必要材料

1. 读取档案头、课程索引和有效偏好，定位本次课程；不能读就说明未恢复，使用用户提供的文件/摘要并标来源。
2. 读取目标进度文件的身份、修订、导学状态/待答I问题、当前概览、教学待答和续学摘要。摘要的`source_revision`、末A/E ID及适用偏好ID/状态须与当前记录一致；索引的修订/SHA-256若不匹配，重读当前概览、相关A/E原记录、补救和复验表，修复缓存。旧文件没有这些字段时也要核对原台账。
3. 摘要是导航缓存，不能代替原始证据判分。当前有失败、待复核或源记录相互矛盾时，核查相关原记录；无法消解就保留历史、注明待复核，不能从“已经掌握”的摘要恢复绿色达成。未来复验仍是计划。
4. 简短报告本次位置、待答/缺口、适用偏好和一个下一动作。只按任务需要读原产物，不重读所有课程和整段聊天。不要因为开始新会话重做诊断，也不要因摘要短而丢失实际提示、量规与失败证据。

每次实际尝试、用户偏好更正、路线/计划变更或暂停交接时更新相应文件。只阅读且无新事实时不为了更新时间重写档案；教学已输入或提出待答也属于课程状态变化。课程摘要和台账在同一次课程保存中更新；课程索引只在新增课程、路径/身份变化、实际保存后刷新所见修订/SHA及定位，不复制原作答。

## 3. 偏好、观察、假设分开

| 类型 | 允许记录 | 使用边界 |
|---|---|---|
| 用户明示偏好F | 原话简述、日期/来源、范围、有效期、确认/撤回状态 | 改表达与负担；不能降低合格依据、补造独立通过 |
| 已观察事实O | 某课程某A/E、实际支持与结果 | 单次表现不能推出永久学习特征 |
| 待验证假设H | 助手推断、证据ID、待确认或待试验 | 明说是假设；不能当已确认偏好或诊断 |

新偏好没有明确范围时，默认只对本课程/当前任务有效，尤其不能把本课预算变成所有课程的时间习惯。只有用户明确要求跨课程通用时才记为全局；已有来源清楚的全局偏好可以沿用。需要跨课应用但范围仍不明时再集中补问，不因建立档案反复询问。

优先采用当前明确指令，再用当前课程/任务范围的有效偏好，最后才用全局已确认偏好。临时约束带范围与结束日/复核点；结束日不明就到约定复核点询问，不能自动永久化。“喜欢图解”不是固定视觉学习类型，也不证明图解效果更好。不要从时间戳差计算投入时长。

偏好变更追加C记录：旧值→新值、范围、用户来源、时间、原因（未知就写未知）、替代/撤回的F-ID。全局F可继续对其他课生效，课程覆盖单列F。撤回不再应用；恢复须新明确依据。不因新成绩重写旧提示条件/量规，不把模型推断冒充用户原话。更正事实时保留更正说明与原记录指向，不重复计为新尝试。

只存完成学习所需信息，概括偏好而非整段聊天。不记录凭据、无关敏感信息或未授权的个人材料。用户要求删除个人记忆时停止使用并按范围处理副本、摘要与索引；实际删除后不在变更历史保留被删内容，只留无敏感值的删除说明（如需）。不承诺清除应用聊天历史或未知外部备份。

## 4. 续学摘要的最小内容

摘要放在各课程进度内，包含：学习者/课程、`source_revision`、末A/E ID、实际更新时间及写入工具/会话别名、导学状态/当前环节、待答I问题及约定状态（旧记录缺失不推断）、当前位置、当前教学待答与支持条件、未解决缺口、计划复验（标未发生）、下一动作及依据、适用F-ID和范围。没有A/E写“无”，不要为填空制造作答。

摘要长度以能准确交接为准，通常几条即可；从原记录重建，过时就重建而非覆盖原台账。进度总览与摘要矛盾时核对台账，不能凭较新时间戳猜谁对。

## 5. 两端保存、冲突与中断

默认单写者：从一个工具结束并保存后，再到另一个工具续学。共享文件不是实时协同编辑。双方都用下述保存助手时，锁与原内容校验能拦截合作写者的冲突；不能保证拦截绕过协议的外部编辑。发现外部编辑先停写、保留待应用内容、重读并核对。

提供标准库[保存助手](../scripts/save_memory.py)，两端均可用本地Python 3.9+调用，无网络依赖：

```text
python <技能目录>/scripts/save_memory.py --root <共享学习根> --target courses/<course-id>/学习进度.md --expected <刚读取的完整文件SHA-256或missing> --content <待写UTF-8临时文件>
```

`--expected`不能取代读文件；先读取并计算旧文件完整字节哈希，再基于它生成候选内容。新文件使用`missing`，不能据此覆盖同名文件。候选内容先核对身份、保留历史、增加`record_revision`；摘要的`source_revision`等于这次修订。助手只保障文件保存，不审核学习判定和修订字段。

助手在根目录独占创建`.ten-step-write.lock`，锁内重读并核对旧哈希，再以同目录临时文件替换单文件。锁存在、内容已变或路径越界时拒绝覆盖；替换前写入失败保留目标原文。任何失败/中断后先重读目标确认是否已保存，再决定合并，保留候选内容。不得自动删另一会话的锁或强制用新哈希重试。遗留锁需核实原会话已停止并由用户确认后处理。两端都采用该协议，不能一端锁内写、另一端直接覆盖。

没有Python或不能创建锁/临时文件时，当前工具只读并给可复制更新，说明“尚未落盘”，由能执行协议的一端保存。不要悄悄退回无校验覆盖，也不因工具缺失阻断教学。

课程进度先保存成功，再以档案自己的旧哈希更新索引与偏好；不是跨文件事务。档案保存失败时明确“课程已保存，档案/索引待同步”，不能声称全成功。下次从已有索引定位并核对真实课程文件；新课程未入索引时给出实际路径，可在用户指定根的`courses/`下只扫描进度文件头恢复索引，不扫其他目录或整盘。同一事件不因重试新增A/E，依据已有ID与原产物核对后合并。

## 6. 旧版迁移与兼容

v3.0进度仍是有效原记录。用户要求接入共享入口时，先保留原文件/可校验备份，赋稳定学习者/课程ID并登记源路径、版本、导入时间和未明条件；可复制到`courses/<course-id>/学习进度.md`，以后明确以该文件为唯一活动副本，原件标历史只读来源，不双向同步。根外来源仅读取用户明确提供的文件，拒绝按文内陌生路径扩散读取。

导入不改旧成绩、A/E编号或量规；提示未知仍未知，历史通过不自动当当前独立可用。缺失原作答不能制造，未来复验不能计入已完成。新字段用真实值或“未配置/未知”，未导入时可继续单文件训练。旧技能不理解新协议时不能与新版同时写共享根；只读交接或先升级技能。跨工具共享的是用户文件，不是把私人档案复制到两份全局技能里。
