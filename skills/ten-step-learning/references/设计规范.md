# 设计规范 · v1.1

本文件记录 ten-step-learning 从 v1.0 升级到 v1.1 的**全部设计决策**，供日后回溯「为什么这么设计」。

决策通过逐轮质询产生（grilling 方式：每一轮把当前可以立刻定的问题一次性摆出、附推荐答案、收敛后再往外推）。共 18 条。

---

## 一、靶心与验收（Q1~Q4）

### Q1 · 靶心：解决什么

**决策**：三个靶心 —— ① 质量不稳定 ② 互动会丢 ③ 专业度不达"专业平均以上"（权重最高）

淘汰的选项：不可复用/不可分发（另由 Q2/Q10 覆盖）、"太重太慢"（本轮不处理）。

**理由**：用户拿着实物（ETF 期权报告）给出的判断是"达不到专业平均水平以上"，这是唯一无法用推测替代的证据。

### Q2 · 交付形态：只在 Trae 用，还是通用

**决策**：通用 skill。Trae / Codex / WorkBuddy 通吃，未来可开源。

**由此产生的硬约束**：SKILL.md 内不得出现任何平台专有工具名；不得使用绝对路径；不得依赖本机安装的其它 skill（含 grilling）。

### Q3 · 十步骨架是否冻结

**决策**：冻结十步编号与顺序，改为在十步之外新增横向层。

**理由**：编号是这套方法的品牌与记忆锚点，一动则历史产出、教学话术、版本对比全部失效。缺的东西（开局问什么、交付长什么样）本就不属于第 1~10 步中任何一步。

横向层最终确定为三个：**开局信息采集层**、**交付规范层**、**难度梯度层**。

### Q4 · 怎么证明改完更好

**决策**：回归测试（用两份已有期权报告做基线防退化）+ 新领域盲测（验深度上限）双验收。

## 二、产物规范（Q5、Q7、Q10）

### Q5 · 报告模板固化

**决策**：新增 `assets/报告模板.html` 与 `assets/骨架模板.html`，统一两代 CSS 命名；v1.0 时代另有一份「通用版产出物」HTML（按当时规则生成，不随本技能分发）。

**关键事实**：两份期权报告的 CSS 变量与类名**逐字相同**（`--bg/--card/--soft/--text/--accent/--ok/--warn/--risk`；`.page/.hero/.badge/.top-grid/.callout/.chip/.footnotes`），说明模板已客观存在，只是活在产出物里、没进 skill；而那份「通用版产出物」用的是另一代命名（`--surface/--ink/--danger`；`.eyebrow/.pill/.quote/.checklist`）。

**理由**：模型每次看不见上一份产出物时就会重新发明版式——这就是版式漂移的机械成因。统一以期权报告那套为准。

**收编**：那份 HTML 的身份被明确为「通用版产出物」，不是模板。

### Q7 · 合规边界

**决策**：高风险领域（投资/法律/医疗/税务）强制免责声明 + 禁止具体标的代码/价位/仓位数字/买卖时点；只允许方法论与模拟推演；必须给出降级改写句式。

**理由**：v1.0 两份报告的合规声明存在**代际差异**（股指那份写了"不构成投资建议"，ETF 那份没写）——同一个 skill 有时带免责有时不带，这正是"质量不稳定"的具体形态。

### Q10 · 跨平台打包

**决策**：拆分为 `SKILL.md` + `references/` + `assets/`，加 `README.md`；`LICENSE` 挂起（待决定是否开源再定）。

**理由**：拆 `references/` 本身与开源无关——三大块新增内容（深度标准、证据规则、必答问题清单）塞进单个 SKILL.md 会臃肿到影响召回与执行。

## 三、流程设计（Q8、Q13、Q15、Q17）

### Q8 · 把生成过程写进 skill

**决策**：速览与精研**串联**，不是并列两档——先出速览骨架 → 用户确认大体判断无问题 → 再进入精研。速览的身份是**精研的前置检查点**。

**理由**：v1.0 只写了"产物层"（报告含哪些章节），完全没写"过程层"（怎么生成的）。这是"每步内容过于简单"的机制之一。

### Q13 · 速览框架的粒度与确认方式

**决策**：(a) 产出**骨架大纲**，不是"完整但浅的报告"；(b) **整体一次确认**，允许按步骤打回重画。

**理由**：若速览就出完整浅报告，等于把"浅"提前固化进用户预期，精研时还得推翻重写；逐步骤确认会把一次流程变成十次往返。

### Q15 · 门外汉怎么验收骨架（用户提出的关键痛点）

**问题**：「作为没学过这个领域的门外汉，很可能无法判断这个骨架内容设计是否合理。」

**核心判断**：不要试图提升门外汉的判断力，而要把"需要判断的问题"替换成"他能判断的问题"——他判断不了"内容对不对"，但完全能判断"覆盖没覆盖、味道对不对、天花板够不够"。

**决策**：四招全上 +

- **M1 外部锚定**：骨架强制附初级从业者真实任务清单（来源见 Q16），逐条标注覆盖情况并给出覆盖率数字。三重用途：让门外汉能验收、充当"专业平均水平"的量化代理指标、作为版本回归的可比指标
- **M2 样品法**：第 3 + 4 步做满精研深度作为"试吃"。这两步连起来正好展示"结论 + 依据 + 评分锚点"，最能暴露深度
- **M3 自曝弱点**：每步强制回答"若这步设计错了最可能错在哪、什么信号说明该推翻它"
- **M4 降维确认三问**：只问"天花板够不够 / 有没有不想要的步骤 / 有没有该覆盖却漏掉的"

**锚定物分岔**（用户确认）：职业型→JD + 资格考纲 + 官方教材目录；学术型→课程大纲 + 经典教材目录 + 综述；商业型→行业报告 + 从业者复盘 + 监管/协会文件。

### Q17 · 精研阶段怎么展开

**决策**：按功能分 4 批 —— ① 框架认知（1~2 步）② 结论与验证（3~4 步）③ 路径与阶梯（5~7 步）④ 考核与复述（8~10 步）；每批落盘存档，最后汇编单一 HTML。

**明确否掉**：逐步确认（与 Q13 的整体一次确认矛盾，且把一次流程变成十次往返）、一次性全展开（内容量会导致后段截断）。

> **一处必须记录的自我修正**：分批的理由**不是**"后段衰减"。诊断数据显示内容薄是全篇均匀分布的（第 3、4 步薄，第 10 步也薄），说明这是**标准问题、不是模型耐力问题**。分批只解决"防丢"和"局部返工"，**不能**自动加深内容。

## 四、内容深度（Q9、Q11、Q12、Q14、Q16）

### Q9 · 每步深度标准改成什么形态

**决策**：A + C。把每步从"必须包含什么"改写为"**必须回答哪些问题 + 答到什么颗粒度**"；并以 C 作为开局输入——先采集"该领域从业者真实任务清单"钉在报告开头当标尺。

**用户追加要求**：**由浅及深要同时作用在两层**——每步的学习内容由浅及深，每步的必答问题难度也由浅及深，覆盖三档（入门基本概念 → 内行人/专业人士 → 专家）。

**明确否掉**：只加字数下限。单独使用必然导致灌水。

### Q11 · "入门"与"专业平均以上"的张力

**决策**：起点只决定**地图从哪儿开始画**，不决定**深度天花板**。零基础只影响表述方式（先讲地图、少用术语），不影响内容颗粒度（数字、阈值、公式、失败案例一个都不能少）。

**理由**：v1.1 之前的实际产出把"读者零基础"当成了降低深度的借口。第 9 步费曼讲解与第 3 步精简简报的存在意义就是——**用大白话讲专业内容，而不是用大白话讲常识**。

### Q12 · 考核题型配额

**决策**：情景判断题 ≥40% / 计算动手题 ≥30% / 概念复述题 ≤30%；每题带**判分点** + **典型错误答案样例**。

**理由**：v1.0 第 8 步 10 题、第 6 步 5 道自测题均为 100% 概念题（计算题 0 道）。概念题只能区分"看过"与"没看过"。而"典型错答样例"是第 8 步"答错先针对性讲解"能落地的前提——模型得先知道错长什么样。

### Q14 · 难度梯度放在哪一层；第 6 步去留

**决策**：两者结合——每步内部铺"入门/专业/专家"三段，同时整体随步骤序号递进。**第 6 步从"五级学习阶梯"改造为整份报告的难度标尺定义章节**。

**理由**：没有共享标尺时每步会各解各的——v1.0 第 4 步那五个 96/92/88/82/68 就是此病的产物。三档统一后在第一步定义、后续引用，第 4 步的评分才有锚点。

**同时发现的结构冲突**：用户把"难度梯度"从第 6 步的局部要求提升为横贯十步的要求，这与第 6 步原有的"五级阶梯"功能重叠。裁决方式是合并——五级的 L1~L5 是"记忆深度"，与"判断力深度"不是一回事（记忆深 ≠ 判断力强）。

### Q16 · 三档难度的判定锚点

**决策**：A 优先、B 兜底 + **强制约束：每一档必须挂一个可检验的产出物**。

- 优先复用锚定物的天然分层（岗位职级 / 教材层次 / 考纲科目分级）
- 锚定物无天然分层时（常见于新设业务、学术型领域）才自造判据，但不得使用"熟悉/掌握/理解"
- **关键约束**：把"专家档"翻译成"能独立完成 X 类任务，并能在 Y 类异常情形下说明理由"，而不是"深刻理解 X"

**理由**：A 单用会失效（考纲常常只有一级、很多领域没有职级体系）；B 单用会退化成形容词。只有挂上可检验的产出物，三档才能反过来驱动 Q12 的题型配额和第 6 步的通过线。

> 附带默认参数：**骨架合格线 = 覆盖率 ≥85%，未覆盖项逐条给理由**。不设"未覆盖也要解释"，模型会把覆盖率写成 100% 糊过去。

## 五、互动与证据（Q6、Q18）

### Q6 · 证据规则

**决策**：允许写具体链接，但强制三件事——① 每条事实性断言带内联角标 `[n]`；② 来源品类配额（官方/一手 ≥40%、教材 ≥20%、从业者一手 ≥20%、反向材料 ≥10%）；③ 无联网时降级为检索式 + 待核实标记，禁止凭印象补链接。

**这一条建立在一项实证之上**：v1.0 两份报告的 21 条来源链接逐条 curl 实测为 **21/21 存活、0 编造、0 不对版**，全部落在 5 个官方域。

**因此推翻了原假设**：原本把"编造资料来源"列为最危险的失败模式，实证证伪。真正的问题是另外两条：

1. **来源没钉在断言上**——ETF 那份 9 条来源全挂文末、正文零角标，读者无法知道哪句话该信哪条
2. **来源品类单一**——21 条全是交易所与证监会官方文件，教材 0 条、从业者一手 0 条、失败样本 0 条。官方文件只回答"规则是什么"，不回答"什么时候会亏、哪种做法被证伪、内行靠什么判断"。**权威性满分，实践性为零。**

### Q18 · 交互进度存在哪

**决策**：独立 markdown 状态文件 `学习进度_<领域>.md`，放在用户工作目录。字段含：当前第几题、已答题与用户原答案、错在哪、是否已讲解、复述是否通过、**已讲解过的知识点**。

**理由**：跨平台一致、人可读可改、不污染交付物。v1.0 定义了交互纪律但没定义状态存在哪，导致断线即等于重新出 10 道题——这正是靶心问题 ②。

「已讲解过的知识点」单列的理由：第 9 步要求"一直讲到用户能完整复述"，没有这一栏，模型会重复讲用户已掌握的部分。

## 六、实证基础汇总

以下数据来自对 v1.0 实际产出物的核验，是本次升级的主要依据。

| 项目 | v1.0 实测 |
|---|---|
| 判据密度 | **≈5%**（定性观点句 80% + 名词清单 15%） |
| 真实案例 / 数据 / 图表 | **0 / 0 / 0** |
| 可验证判据总数 | ETF 报告 ≈1 条；股指报告 ≈5 条 |
| 反例与失败样本 | **两份均为 0 条** |
| 第 4 步评分 | 96/92/88/82/68，0 依据、0 来源、0 算法 |
| 第 6 步达标标准 | 全部为"能说出…""能算出…"，**无通过线** |
| 第 8 步题型 | 10 题 **100% 概念题**，计算题 0、情景题 0 |
| 隐含读者 | 零基础准入者（防坑科普）→ 与"专业平均以上"目标存在天花板错位 |
| 来源链接真实性 | **21/21 存活、0 编造、0 不对版**（5 个官方域） |
| 来源品类 | 官方文件 21 条；教材 0、从业者一手 0、反向材料 0 |
| 内联角标 | 股指有 `[1]~[12]`；**ETF 为 0** |
| 报告实际板块 | hero 封面、先看全貌、第 1~10 步、附加提醒、参考来源（后 4 个 v1.0 未定义，已收编） |

**一句总结**：v1.0 的每条形式要求都被满足了（有分数、有自测题、有 60 秒讲稿），而内容可以在完全满足形式的前提下归零。**这不是模型偷懒，是标准本身允许它这么干。**

## 七、版本对照

| 维度 | v1.0 | v1.1 |
|---|---|---|
| 合格线形态 | 必须包含 A/B/C（形式可满足） | 必须回答哪些问题 + 判据密度（形式不可糊弄） |
| 生成流程 | 未定义 | 开局采集 → 速览骨架 → 精研 4 批 → 交付 → 互动 |
| 深度标尺 | 无 | 三档统一定义在第 6 步，每档挂可检验产出物 |
| 难度梯度 | 第 6 步局部（L1~L5 记忆深度） | 横贯全篇（判断力深度，每步三段 + 整体递进） |
| 门外汉验收 | 无 | 覆盖率校验 + 样品 + 自曝弱点 + 确认三问 |
| 证据 | 一句"不得编造证据" | 内联角标 + 品类配额 + 降级分支 + 来源核验 |
| 引用纪律 | 两种形态都算合格 | 强制内联角标 |
| 考核 | 全概念题 | 情景 ≥40% / 计算 ≥30% / 概念 ≤30%，带判分点与典型错答 |
| 互动进度 | 未定义 | 独立状态文件，含"已讲解过的知识点" |
| 合规 | 时有时无 | 高风险领域强制免责 + 禁具体操作指引 + 降级句式 |
| 版式 | 代际漂移 | `assets/` 内固化模板，统一 CSS 命名 |
| 跨平台 | 隐含绑定 Trae | 禁用专有工具名与绝对路径，跨平台可迁移 |
