# 设计依据、版本与验证 · v3.3.1

## 0. 版本编号约定

沿用2026-10-14确认的规则，历史版本不重命名，判定自上而下：
| 形式 | 条件 |
|---|---|
| X.0 大版本 | 整体结构、框架或逻辑实质改变，包括十步、模式、评价口径、索引层级或参考划分 |
| X.Y 小版本 | 新增独立功能/模块，但未命中大版本条件 |
| X.Y.Z 补丁 | 既有机制内修正规则/字段/表述，不改结构 |

历史v3.0保持十步和两模式，但改变跨任务路由、评价适配和结业/当前状态逻辑，并增加配置参考划分，命中第一条，故不是v2.6或v2.5.3。

版本命名不豁免验证。按受影响行为做结构、固定回放与独立代理检查；不要求每个补丁重做真人对照，但不能由“补丁”推断学习效果不变。效果声明需匹配真人证据，旧成绩保留当时版本、量规和条件。

## 1. 共同机制与证据边界

没有唯一适合任意专业的科学十步顺序。以下支持相关原则，不是本技能或六类配置效果试验；六类是可检验设计提案，不是完整学科分类学。

| 原则 | 来源 | 设计推导及限制 |
|---|---|---|
| 目标—活动—评价对齐 | [Biggs 1996](https://doi.org/10.1007/BF00138871) | 先定产物判据，理论不验证AI教练 |
| 先修与支持适配 | [Sweller等2019](https://doi.org/10.1007/s10648-019-09465-5) | 依已有知识与表现调支持，不只按题目层级 |
| 示范、练习与解释 | [IES 2007](https://ies.ed.gov/ncee/wwc/PracticeGuide/1) | 支持相关学习机制，不验证固定配比与完整十步 |
| 自我解释 | [Bisra等2018](https://doi.org/10.1007/s10648-018-9434-x) | 解释按任务取形式，无统一儿童受众门槛 |
| 间隔与保持 | [Cepeda等2006](https://doi.org/10.1037/0033-2909.132.3.354) | 间隔按保持目标，不规定统一日历 |
| 迁移需观察 | [Pan与Rickard 2018](https://doi.org/10.1037/bul0000151) | 陌生任务验证，不从旧题推断 |
| 评价解释与切分 | [AERA/APA/NCME 2014](https://www.testingstandards.net/uploads/7/6/6/4/76643089/standards_2014edition.pdf) | 为分数/条件给理由，不提供普适90/80/75 |
| 学科实践差异 | [Shanahan等2011](https://doi.org/10.1177/1086296X11424071) | 小样本专家研究支持关注不同阅读用途，不能推广成学科刻板印象 |
| 数学来源判断的反证 | [Weber与Mejia-Ramos 2013](https://doi.org/10.1177/1086296X12469968) | 不能由有效证明判据推断数学专家不看来源 |
| 科学解释与工程设计 | [NRC 2012第3章](https://www.nationalacademies.org/read/13165/chapter/7) | 解释/设计依据不同；K—12框架不是成人技能实验 |
| 概念与程序迭代 | [Rittle-Johnson等2001](https://siegler.tc.columbia.edu/wp-content/uploads/2020/10/2001-Siegler-Alibali.pdf) | 小数学习实验不等于所有专业顺序证据 |
| 有条件先探索后教学 | [Kapur 2014](https://doi.org/10.1111/cogs.12107) | 特定数学任务，不支持所有零基础者无指导探索 |

P5、P6的具体配置主要来自目标—表现对齐与现场边界的设计推导，本轮未系统验证语言、动作及艺术教育效果，实际使用仍需相应领域标准与反馈。未复制论文、课程或第三方模板，保持仓库MIT声明。

## 2. v3.0变更与取舍（保留设计依据）

本节及各历史版本条目用于追溯设计，不作为现行教学指令；其中“提过即已教/可考”、全域数值走查和“模式只决定记成绩”等旧措辞，分别以当前深度标准、教学材料与入口为准。

先修六类一致性：①以任务能力蓝图替代跨领域题型配额；②支持量依先修/表现，比例有预计时长口径并允许有据缩减冗余；③修评分分辨率与辅助/独立解释；④统一小节/单元/板块合取和延迟失败状态；⑤索引与先修/路线分开；⑥教学、参考解和AI评分加入核验/待复核。

再加入P1—P6可组合配置，改变示范、练习、综合评价与保持证据。数值90/80/75、三级索引、每轮定位与地图按需更新等个人偏好保留；没有以研究名义替用户另设一组“科学阈值”。原题型配额可作为声明的个人/考试预设，不再全局强制。

私有档案与课程原记录分开，索引和摘要是可重建缓存，不替代A/E台账。偏好分明示、观察和假设；跨课程引用带作用域，跨工具默认单写者。标准库保存助手只保障合作写者单文件替换，不是实时协作、跨文件事务或后台同步。没有接入Hindsight，不声称增加文件就提高学习效果。

## 2.4 v3.2.2出题前检查

落实2026-10-20两次真实反馈，新增三条纪律，均落在既有评价机制内，不改十步、流程、索引或模板结构：

1. **可考性门槛**：入卷须有示范/练习，或在两处不同性质材料中用过，或属"规定型"且已显式列为记忆项；否则标"探测题"，只记录不计分、不触发需补救。触发事实：单元小测考了"交收日"，该点此前只在地图与输入表里各出现一次（都是表格一行），无示范无练习，学习者据"没教过却考了"申诉，核查后**部分成立**——出现过，但交付强度不足以支撑扣分。
2. **同一检验不得重复判分**：两个判分点不得考同一事实。触发事实：同一份小测里，前一题问"交收日"、后一题问"到期日"，实质都压在"第四个星期三"上，学习者直接指出题目重叠。
3. **占位假设不得升格为条件**：助手为推进流程填的预算/时长/题量须当场标为待验证假设并复核，不得在后续文档里成既定条件。触发事实：学习者追问"12小时预算是哪里来的、我有约定过吗"——核查无用户依据，系助手2026-10-14自行填入的占位值，却被后续文件当作条件沿用。
4. **两种模式是串联而非二选一**：正常顺序为先设计并确认（地图、示范、材料、评价标准），再训练并按真实产物记录；"模式"只决定是否把表现记成绩。触发事实：学习者问"为什么不先把路线、示范、材料设计好交给我看，然后再持续训练"——现有措辞把两段写成了并列选项，读起来像要二选一。

**性质与边界**：三条都是把"评价公平性"写进规则，属于既有机制内新增约束，按 §0 判据属补丁级。它们**不提高也不降低**任何分数线，只约束"什么能考、怎么问、假设怎么记"。**不足以据此宣称学习效果改善**；与 v3.2.1 之间不需重新做对照实验，对照基线仍是 v1.1。

## 2.5 v3.2.3提问台账与易混淆对照

落实2026-10-21两项学习者提议，均落在既有教学与检验机制内，不改十步、索引、模板结构与分数线：

1. **课后提问与疑问台账**：每小节末留**可选**提问口；问答记入进度文件的疑问台账（原问法、回答要点、复述/追问、状态）。提问**不计分、不建 A/E、不改变四档状态**——只有随后的复述或追问是否准确才可能成为证据；单元小测可抽**1 题**，且只从「已澄清·待复述」「仍存疑」中抽，已复述者不再抽。触发事实：学习者答完 1.2.2 后主动追问"一级权限的第三项算不算前两项的补充说明"，方向正确且指出条款结构问题；该问题如未被提出，条款结构会一直停留在"三项并列"的浅层，而任何只考"三项是什么"的测验都测不出来。同期另观察到"提问未被记录→下一节重复踩同类坑"的链条。
2. **集中输入三段结构**：新内容按「核心一句 → 易混淆对照（两列并置，各带实例与反例）→ 常见错法及为什么错」组织，且**对照必须成对并置**，只提醒不对比等于没教。附带一条边界：**提示中出现的内容即属"已教"**，按 §2.4 可考性门槛可计分，故不能靠"随口提一句"免责。触发事实：1.2.2 练习中学习者把条文类别「买入开仓」「保证金卖出开仓」记成具体策略「买入认购」「卖出认沽」——原文虽提过"认购与认沽都算"，但未把"类别 vs 实例"并排摆出，结果仍被压缩成一个策略。

**性质与边界**：属既有机制内新增规则与字段，按 §0 判据为补丁级。**不足以据此宣称学习效果改善**；与 v3.2.2 之间不需重新对照，基线仍是 v1.1。本次仅更新仓库源码与 WorkBuddy 副本，Trae 全局与项目级副本待版本调整结束后统一同步；不提交、不推送、不打标签。

## 2.6 v3.2.4记号与公式的交付前提

落实2026-10-22一次真实教学事故，新增四条，均在既有教学与评价机制内，不改十步、索引或模板结构：

1. **公式三前置**：任何公式／记号用于下结论之前，须先给①符号表（含义＋单位＋一个数值）②它要回答什么③一次数值走查，缺一不得进入结论。触发事实：一次小节输入在**未定义 S、K 与 min/max 用法**的前提下直接写出 `min[(2S−K), S]×10%` 并据此推出"最大涨幅只剩 0.5%"，学习者明确反馈"来得太突然、完全理解不了、推导不过去"——该内容虽在数值上正确，但**读者在符号层就被卡住**。
2. **机制须带失败场景**：每个新机制给出"没有这条规则会怎样"的具体情形。触发事实：同一次输入给出"熔断需同时满足 ≥50% 与 ≥5 个最小报价单位"却未举例，学习者反馈"看不懂在说什么"；补入"价格 0.0002 跳一格即 50% 却不触发"的实例后，第二条条件的作用才成立。
3. **反例必须可算**：反例要写出"按错误理解会算出多少、差几倍"。触发事实：原反例只说"会高估"，修订后给出"0.3000 对 0.0150、高估 20 倍"才有说服力。
4. **只作了解的记号须显式标注**；并配**交付前自检**（通读找未定义符号，补或删）。这一条针对"作者表达流畅、读者却卡在符号层"的失败型态——它无法从文本流畅度上察觉。

**性质与边界**：属既有机制内新增交付约束，按 §0 判据为补丁级，**不改变任何分数线**；触发它的是一次**输入被判定作废并重做**的事实（首版未作答、无成绩，故不涉及成绩改写）。**不足以据此宣称学习效果改善**；与 v3.2.3 之间不需重新对照，基线仍是 v1.1。

## 2.7 v3.2.5改写已有材料的保值规则

落实2026-10-23第二次真实教学事故（v3.2.4 同源事件的后续），新增一条四步规则，落在既有教学与评价机制内：

1. **先问**：改写前把旧版「已教要点清单」交学习者，问"是否已学完"。
2. **未学完 → 逐条核对**是否保留，**不得整块替换**。
3. **删除须显式标注「该项退出教学」**并留痕，**不得静默消失**。
4. **退出教学的点不得再进计分题**（失去 §4 可考性）；要重新计分须先重新交付。

**触发事实**：一次小节输入因"公式未定义"被作废重做（v3.2.4 的来源），重写时**把旧版"交易时段"整块漏掉**，却仍在练习中考核该点，形成"没教就考"；学习者作答后才暴露（其答案还漏掉午休时段）。按可考性门槛，该题当场标为探测题、不计分。**"先问"这一步是学习者本人提出的**——作者原稿只写"删除须标注"，默认必须保留，会把已学透的冗余一路滚下去。

**性质与边界**：属既有机制内新增流程约束，按 §0 判据为补丁级，**不改变任何分数线**；不足以宣称学习效果改善；与 v3.2.4 之间不需重新对照，基线仍是 v1.1。本次仅更新仓库源码与 WorkBuddy 副本，Trae 全局与项目级副本待版本调整结束后统一同步；不提交、不推送、不打标签。

## 4. 验证分层

- 结构：入口/配置版本、相对引用、模板标签和必需状态字段。
- 规则：评分离散档、局部/综合冲突、延迟失败、先修插入和等价解。
- 代理：六类和混合路由是否实际改变教学/任务/评分；提示条件、未来结果与现场边界是否保留。
- 真人：相近起点、同目标预算、平行陌生任务、尽量盲评，记录独立、延迟、迁移、时间、负担和退出。
- 专业：多个真实任务和相关人员反馈，核查文字不能测到的操作与协作。

本轮对照演练只观察助手行为与隔离文件读写，不证明真人学会、真实Codex/Trae界面兼容或新版学习效果优于基线。结构检查不能替代代理演练，单次代理演练不能替代真人研究。源码说明只记可复现的方法与边界，原始演练放独立管理位置。
