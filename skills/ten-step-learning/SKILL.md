# 十步法学习引擎 v1.1

## 何时使用

- 用户说「按十步法带我学 XX」「用十步法拆解 XX」
- 用户要求系统学习、快速入门、摸清某个专业或行业
- 用户要把陌生领域拆成可研究、可练习、可复述的一整套流程
- 用户已学过一轮，要求「学透 / 对标从业者水平 / 精研」

## 三条底层原则（先读这三条，再读流程）

**1. 形式可满足，判据不可糊弄。**
禁止把合格线写成「必须包含 A/B/C」——「包含」一句话就能满足，这是本引擎 v1.0 产出「章节齐整、内里发飘」的根因。所有要求一律写成「**必须回答什么问题 + 答到什么颗粒度才算过关**」。

**2. 产物层与过程层分开。**
十步是报告里的十个章节（产物）；从采集目标到交付文件是生成流程（过程）。两层都要执行，不得只填章节。绝大多数失败不是不会填章节，是没走流程。

**3. 门外汉必须能验收。**
用户是该领域外行，没有能力判断内容对不对。所以每一次要用户确认的环节，都要把「需要领域知识才能审的问题」替换成「只需要常识就能审的问题」——覆盖率、味道、天花板，而不是「这个设计合不合理」。

> **禁止事项**：不得依赖任何特定平台的专有工具名（搜索工具、子任务、特定代理等），一律表述为「使用当前环境可用的联网检索能力」；不得使用绝对路径；不得依赖本机安装的其它 skill。

## 阶段 0：开局采集（横向层 · 必做）

一次问完，**最多 5 个问题**，不要连续追问：

1. **目标领域**是什么
2. **目标档位**：入门 / 专业 / 专家（默认 **专业**）
3. **你的起点**：完全外行 / 有点耳闻 / 有相邻领域经验
4. **你的用途**：能看懂不被忽悠 / 能上手做 / 能形成并辩护自己的判断
5. **是否属于高风险领域**（投资 / 法律 / 医疗 / 税务）

用户不回答时，按领域类型取默认值并**明示假设**后继续推进，不要卡住流程。

**起点只决定地图从哪儿开始画，不决定深度天花板。** 不要因为用户「零基础」就把内容降级成常识科普——零基础只影响表述方式（先讲地图、少用术语），不影响内容颗粒度（该有的数字、阈值、公式、失败案例一个都不能少）。

### 采集锚定物（决定后续所有深度标准）

先判定领域类型，再选锚定物（详见 `references/领域适配.md`）：

| 领域类型 | 锚定物来源 |
|---|---|
| 职业型（有岗位、有资格认证） | 招聘 JD + 从业资格考纲 + 官方教材目录 |
| 学术型（学科、理论） | 课程大纲 + 经典教材目录 + 综述论文 |
| 商业型（新设业务、无成熟职级） | 行业报告 + 从业者公开复盘 + 监管/协会文件 |

从锚定物中抽出 **15~25 条「初级从业者真实任务项」**，形成任务清单。**这份清单是后面覆盖率校验的标尺，也是「专业平均水平」的量化代理指标。**

---

## 阶段 1：速览骨架（精研的前置检查点）

用 `assets/骨架模板.html` 产出五块内容：

1. **十步骨架**：每步一句话定位 + 该步必答问题预览 + 三档难度落点 + 预计判据数量
2. **覆盖率校验表**：任务清单逐条标注「覆盖 / 部分覆盖 / 未覆盖」+ 未覆盖理由；末尾给出覆盖率数字
   - 未覆盖理由只允许三类：超出目标档位 / 属于另一分支 / 确实缺失
   - **合格线：覆盖率 ≥85%**，且未覆盖项逐条有理由。达不到就补，不要写理由糊过去
3. **样品（试吃）**：第 3 步 + 第 4 步做到**完整精研深度**，其余九步仍为骨架
   - 为什么是这两步：它们连起来正好展示「结论 + 依据 + 评分锚点」，最能暴露深度和味道
4. **自曝弱点**：每一步强制回答一栏——「如果这一步的设计是错的，最可能错在哪？出现什么信号说明它该被推翻？」
5. **确认三问**：只问用户这三个他答得出的问题
   - ① 三档难度的天花板是不是你要的？
   - ② 有没有你不想要的步骤？
   - ③ 覆盖清单里有没有你特别在意却漏掉的？

**禁止**问用户「你对这一步的设计满意吗」这类他无法判断的问题。

### 确认规则

- **整体一次确认**，允许按步骤打回重画，允许直接改档位
- 用户改档位后，只需重画受影响步骤的骨架，不必全部重来
- 确认通过前**不得**进入精研

## 阶段 2：精研（按功能分 4 批）

| 批次 | 覆盖步骤 | 产出重点 |
|---|---|---|
| 批 1 · 框架认知 | 第 1~2 步 | 角色视角与矛盾清单 |
| 批 2 · 结论与验证 | 第 3~4 步 | 简报、关键发现、靠谱度评分 |
| 批 3 · 路径与阶梯 | 第 5~7 步 | 资料路线、难度标尺、时间块与实战项目 |
| 批 4 · 考核与复述 | 第 8~10 步 | 题目集、费曼讲解、速查表 |

**每批完成即落盘**为中间 markdown 存档（防止中途失败丢掉全部进度），最后汇编为单一自包含 HTML。

> 读这一条时不要误判：分批**不能**自动加深内容。诊断数据显示内容薄是全篇均匀分布的（第 3、4 步薄，第 10 步也薄），说明这是**标准问题，不是模型耐力问题**。分批只解决「防丢」和「局部返工」，加深内容只靠下面的判据密度与反例配额。

---

## 阶段 3：交付

- 用 `assets/报告模板.html` 的骨架与内置 CSS 逐节填充；**不得重新设计版式**
- **自包含**：不得引入 CDN、外链图片、外部字体，全部内联
- 文件名：`<领域>_十步法学习报告.html`
- 报告实际包含 4 个额外板块（v1.0 未定义、但产出里一直存在，现已收编）：**hero 封面、先看全貌、附加提醒、参考来源**
- 交付后给简短摘要 + 下一步提示，不要长篇复述报告内容

---

## 阶段 4：互动（考官模式 / 费曼复述）

- 进度写入工作目录下的 `学习进度_<领域>.md`（格式见 `references/交互与状态.md`）
- **每次开始互动先读该文件**；不存在则新建
- 纪律：**一次只问一题、不得跳题、答错先做针对性讲解、讲解后确认用户已修正理解再进入下一题**
- 费曼模式：讲到用户能完整复述为止，中途不换话题
- 状态文件必须单独记录**「已讲解过的知识点」**，避免重复讲用户已掌握的部分

## 十步定义

| 步 | 定位 | 核心要求 |
|---|---|---|
| 1 | 五类专家视角 | 实践者 / 研究者 / 怀疑者 / 经济学家 / 历史学家；每类须给出立场、核心证据、专属隐藏信息 |
| 2 | 矛盾清单 | 观点冲突、证据强弱、共识点、行业盲区；证据强弱必须给判定依据 |
| 3 | 精简简报 | 60 秒讲稿 + 按可信度排序的 5 条关键发现 + 可执行行动建议 |
| 4 | 靠谱度评分 | 每条发现给分数 + 命中锚点 + 扣分项 + 加分条件 |
| 5 | 一周学习路线 | 5 份资料，每份须回答 7 问（含利益立场、反驳者、时效性、失效条件） |
| 6 | **难度标尺定义章节**（原「五级学习阶梯」改造） | 三档难度的能力判据、**可检验产出物**、通过线、错误容忍度、典型失败者画像 |
| 7 | 20 小时攻坚 | 时间块分配依据 + 每块可检验产出 + 卡壳解锁条件 + 最小实战项目的评分标准 |
| 8 | 考官模式 | 10 题从易到难；题型配额 + 每题判分点 + 典型错答样例 |
| 9 | 费曼讲解 | 讲给 12 岁小孩；含复述模板、易讲错处、隐喻失效边界、复述通过标准 |
| 10 | 速查表 | 核心概念 / 关键角色 / 关键流程 / 关键指标 / 最常见误区 / 最该优先验证的问题 |

**每一步的完整必答问题清单（5~8 问）、三档产出物、防敷衍规则，见 `references/各步必答问题清单.md`。**

> 第 6 步是整份报告的**难度标尺定义处**：三档在这里一次性定义，后面每一步引用它，**不得各步自定义**。v1.0 那些无依据的 96/92/88/82/68 裸评分，就是没有共享标尺的产物。

## 三条横向红线（每一步都必须满足）

**红线 1 · 判据密度**
每步至少 **5 条可验证判据**（含具体数字、阈值、条件边界、时间窗口、来源年份之一）；第 3、4、5、6、7 步至少 **8 条**。单步内纯定性观点句占比 **≤40%**。禁止以形容词收尾。

**红线 2 · 反例配额**
每步至少 **1 条**反例 / 失败样本 / 争议点；全篇至少 **5 条**。

**红线 3 · 证据与角标**
- 每条事实性断言必须带**内联角标 `[n]`**，来源不许只堆在文末；无来源的句子必须显式标为「推断」
- **来源品类配额**：官方/一手文件 ≥40%、经典教材或公认书籍 ≥20%、从业者一手材料 ≥20%、反向材料（失败样本/监管处罚/争议）≥10%
  - 只堆官方文件会得出「规则知识」而非「实践知识」——权威性满分、实践性为零
- 无联网能力时**降级为检索式**（书名 + 关键词 + 文件编号）+ 显式「待核实」标记；**禁止凭印象补链接**

违反任一条红线的输出即为不合格，必须补写后重发。

## 合规边界（高风险领域）

涉及投资 / 法律 / 医疗 / 税务时**强制**执行：

- 报告必须含明确的免责声明
- **禁止**输出具体标的代码、价位、仓位数字、买卖时点
- 只允许方法论、判断维度与模拟推演
- 必须给出**降级改写句式**：把「该买哪个执行价」改写成「该用哪几个维度筛选执行价」

详见 `references/证据规则.md`。

---

## 风格要求

直接、具体、少空话。先讲地图，再讲机制，再讲例子。重点是帮用户形成判断模板，不是堆信息。不写成泛泛励志文。
