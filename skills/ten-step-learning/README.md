# 十步法学习引擎（ten-step-learning）

**版本：v2.5.2。** 从实际目标出发，建立专业学习路径，支持逐单元示范、练习、反馈、延迟复验和继续学习。适用于概念、操作和判断任务；需要设备、现场实践或专业监督的能力，应增加相应验证。

## 怎么开始

```text
按十步法带我学 Python 数据分析。
我零基础，想独立清洗业务表并说明处理依据。
每周能投入5小时；采用持续训练，先给骨架和一个示范练习。
```

也可点名 `$ten-step-learning` 或“使用 ten-step learning”。调用机制取决于所用助手。

只想研究领域、获得资料时：

```text
用十步法拆解供应链管理，采用研究与规划模式。
重点是库存与需求预测，先给骨架，确认后交付学习手册。
```

“带我学”通常进入持续训练；“只要报告”通常进入研究与规划。起点、用途、预算、工具、输出位置可以一次提供，不必等助手重复问。暂缺信息可以做规划假设，用户尚未答题的状态保持“未观察”。

## 两种模式

| 模式 | 交付与互动 | 如何看待结果 |
|---|---|---|
| 研究与规划 | 目标、地图、证据、示范、练习设计和HTML手册 | 说明规划与资料质量，不认证学习者能力 |
| 持续训练 | 实际诊断、逐单元练习、反馈、复验与进度文件 | 依据用户产物和表现记录阶段能力 |

共同流程：目标与范围 → 骨架与示范样品 → 整体确认 → 研究手册或当前单元训练。已有明确确认可复用；允许局部调整、缩小任务或暂停。

## 新十步

| 步 | 内容 |
|---|---|
| 1 | 目标与能力标准 |
| 2 | 起点与先修诊断 |
| 3 | 最小领域地图与核心机制 |
| 4 | 标准任务示范 |
| 5 | 引导练习与指导渐撤 |
| 6 | 独立实践与反馈补救 |
| 7 | 变式、证据与批判判断 |
| 8 | 综合评价与陌生任务 |
| 9 | 延迟复验与自我解释 |
| 10 | 工作支持与持续成长 |

十步是导航，具体任务按先修关系和表现推进。自我解释、低风险检查和复习穿插于每个单元，第8、9步表示综合检查点。资源开局规划、单元内按需提供，末尾更新长期路线。

## 学习怎样推进

每个单元采用：机制 → 完整示范 → 解释原因 → 补全练习 → 独立练习 → 反馈补救 → 变式 → 延迟复验。指导随实际表现渐撤，复杂度提高时可重新给支持。

- 零基础影响先修、信息量、任务难度和节奏；长期目标可以保持。
- 入门、专业、高级/专家任务层级由具体任务和判据定义，当前表现另列；阅读高级材料不获得专家身份。
- 时间预算用于安排第一轮任务。20小时可以是可选预算，不是整个专业的精通期限。
- 关键能力要分别通过，课程覆盖与即时答对不能代替保持、迁移和真实工作验证。

## 继续、复习与暂停

```text
读取工作目录中的学习进度_数据分析.md，继续上次未完成的能力点。
```

```text
先让我不看资料解释上次的机制，再给一个陌生案例；根据结果安排复习。
```

```text
暂停，保存提示程度、薄弱点、产物和下次动作。
```

进度文件区分已讲解、提示下完成、独立通过、延迟通过和迁移通过。已经讲解过仍可能需要复验。跨会话/工具续接须能访问同一工作目录；技能安装不会自动同步私人学习记录。v1.1进度在备份后按能力映射迁移，旧题号不能直接套用新编号。

## v1.1 与 v2.0 对照

仓库标签`v1.1`保留原始主流程、参考文件、模板和说明；`v2.0`采用新编号。比较请使用两个标签各自的完整技能目录和相同学习预算，不混用不同版本模板。

v2.0前置能力目标和诊断，新增示范与指导渐撤，将测验、解释、复习嵌入训练，分开证据评价与能力评价。旧固定来源/题型比例、85%覆盖认证、十题八过和五年专家等通用硬线已取消。

此改版由文献与设计评审支持，**尚不能据此宣称真人学习效果或跨平台运行效果优于v1.1**。结构检查、独立代理场景演练与真人学习试验应分别记录；测试只覆盖指定场景。精通某专业还需要多任务实践、可靠反馈和相应外部验证。

## v2.1 变更

v2.1 是 v2.0 的**单点补丁**，不改变十步顺序、模式划分、评价口径与模板结构，只补一条原本缺失的记账规则：

- `references/领域适配.md` §3 新增「**假设起点下的示范须标注并可重做**」：骨架先于诊断交付，其中的第 4 步示范只能基于明示的假设起点编制；须在样品处标注该假设；诊断结果与假设不符时须重做示范或显式标注差异；此类示范不得记为"已讲解"，也不得计入任何能力证据。

**触发原因（一次真实学习会话的观察）**：骨架样品已完整印出正确算式 `0.1200 × 10000 = 1200 元`，用户在同批诊断中仍把合约成本答成别的数值。这说明"示范已给出"与"用户已掌握"是两件事，而 v2.0 只在原则层面写了"不能伪造用户完成记录"，没有规定**示范依据的是谁的起点**以及**诊断后如何处置**。v2.1 补上这一条。

其余文件仅同步版本标记（`metadata.version`、各参考文件标题、模板徽标与页脚、`config.json`）。`设计规范.md` 正文中描述 v2.0 设计过程的表述**按历史保留**，未随版本号改动。

## v2.2 变更

v2.2 同样是**单点补丁**，不改十步顺序、模式、评价口径与模板结构，只补一条**交付顺序约束**：

- `references/领域适配.md` §3 新增「**第3步地图必须先于示范与练习交付**」：进入第 5 步练习之前，必须先交付第 3 步的最小领域地图与核心机制；地图可以是独立文件，但必须先在骨架中出现其结构；每个单元开始时先给机制输入，再示范，再练习。
- `assets/骨架模板.html` 增加「**第3步 · 最小领域地图与核心机制**」区块（层/块 × 必要概念与关系 × 对应能力ID × 现在读什么），插入位置在「新十步导航」之后、「第4步示范」之前，使学习者的第一次接触是地图而非示范＋测验。

**触发原因（一次真实学习会话的用户反馈）**：用户直接问"是不是还没按十步法正式开始学习啊"——他的第 1、2 步已做，第 4、5 步也做了，但**第 3 步被跳过**，因此拿到的是零散知识点、看不到体系。根因不在执行者的疏忽，而在结构：骨架样品的样品只有"第 4 步示范 + 第 5 步练习"，第 3 步的地图不在骨架里，加上"可继续不依赖诊断证据的导入示范"这一条，执行者会自然地先出示范与练习。v2.2 把顺序写成硬约束。

**仍不适用的结论**：本条同样只来自单一领域、单次会话的反馈，**不能据此宣称学习效果改善**。它约束的是交付顺序，不是效果。

## v2.3 变更

v2.3 补的是**教学与检验的配比**，以及第 3 步的**讲法**。这是三个补丁里改动最实质的一次：

- `references/交互与状态.md` 新增 **§8**：
  - **§8.1 配比随知识点层级分层**——初阶 **8∶2**、中阶 **6∶4**、高阶 **5∶5**；层级越高越依赖实操检验。并明确**不得跳过第5步的"跟做"与"补全"直接进入独立作答**。
  - **§8.2 通过线**——一个知识点记"掌握"须**同时**满足"能讲清机制"与"能独立做对"；检验时点可分层（初阶允许把"做对"放到层级末小测或延迟复验）。
  - **§8.3 失败回溯**——高阶没过要先查中阶先修、中阶没过再查初阶概念，**回到最早出现漏洞的层级**补课，不在同一题上反复加难度。
  - **§8.4 提问纪律**——凡"赚／亏""对／错"的判断必须写明结算时点或判断视角；题干有歧义须先修正题干，**不得记成用户错误**。
- `references/各步必答问题清单.md` 第3步新增**三步讲法**：先整体串一遍框架（含划分理由与承前启后）→ 再按层级由浅入深讲含义与用途 → 每层级末做整体回顾＋概念层小测。并规定**用途必须开局确认**、**"先知道后精通"的内容不得压成一行**。
- `SKILL.md` 的「每单元学习循环」段加入配比与回溯的入口指引。

**触发原因（同一次学习会话的用户反馈）**：用户统计后指出"来来去去都是那几个知识点在反复测试，完全没有新知识点的输入"，并追问"希腊字母这类内容应该由哪一步教"。复盘后确认：该会话 9 次任务全部是无提示独立作答、教学材料只有 2 份，**教∶考约 2∶9**，且第5步的"跟做""补全"两级被跳过——教学被降级成了测验。v2.3 把配比、通过线、回溯和讲法写成显式规则，并补上提问纪律。

**关于这四条规则的来源要说清楚**：它们来自一位学习者的**使用体验判断**，不是学习科学实验结论。分层比例（8∶2 / 6∶4 / 5∶5）是可调整的默认值，不是普适门槛；v2.3 亦不足以宣称学习效果改善。

## v2.4 变更

单点补丁，改**示范的质量下限**：

- `references/各步必答问题清单.md` 第4步新增「**示范里每个中间量都必须解释来源**」：出现的系数、指数、分母、常数都要交代从哪来（例如 `½ × Γ × (ΔS)²` 里的 ½ 与平方），并给几何解释；只写算式不解释来源等于没有示范。同时要求写明近似条件与略去了哪几项，并在示范后附自查问题。

**触发原因**：v2.3 之后按新配比交付的第一个示范（希腊字母四通道叠加）里出现了 `½ × 2.0 × 0.05²`，学习者直接反馈"没看懂为啥是这个式子——我看懂了 Γ≈2.0、标的变化 0.05，但没明白 ½ 和 0.05² 代表什么含义"，并要求以后示范题的计算过程都要详细解释。

**这条的教训是一般性的**：示范失效往往不是因为"没给答案"，而是因为**跳过了中间符号的来源**。学习者卡在符号上，方法就传不过去。v2.4 把"可复现"写成了示范的验收条件。

## v2.5 变更

v2.5 补的是**可感知的进度定位**。此前版本只有“证据表”，没有“地图上的位置”：

- `references/交互与状态.md` 新增 **§9 进度索引与里程碑**：
  - **§9.1 三级索引结构**——**大板块＝里程碑／中单元＝一级节点／小节＝二级节点**；编号格式 `B板块.单元.小节`；每小节挂「编号｜名称｜层级｜状态｜能力ID｜证据ID」。**地图坐标管定位、能力ID 管验收，两者双层保留、不合并。**
  - **§9.2 状态四档**——`未开始／已输入／已练／已通过`，另设并列标记 `待复验`；**禁止**用百分比或单一等级压缩状态。
  - **§9.3 进度总览条**——进度文件顶部固定区块 ＋ **每轮回复末尾一行**“当前位置／计数／下一站”。
  - **§9.4 节点与里程碑触发**——每小节即时更新（二级节点）、每中单元一次一级节点确认、每大板块一次里程碑；**仅当该节点下全部小节已通过时才点亮**；里程碑文本只能是事实陈述，**禁止等级、徽章、打卡等与掌握无关的奖励**。
  - **§9.5** 第 3 步地图必须同时是**索引课程表**，与进度表**共用一套编号**；后续只能追加编号、不改旧编号。
  - **§9.6** 可视化进度图**首次生成一次**，此后仅在用户要求时更新。
- `references/各步必答问题清单.md` 第 3 步：产出追加“索引课程表”要求，并给出粒度下限（大板块下须有多个中单元、中单元下须有 2~4 个小节）。
- `assets/学习进度模板.md`：新增「进度总览」与「进度索引（三级·唯一编号来源）」两节及「节点达成记录」表。
- 新增 `assets/进度地图模板.html`：自包含可视化进度图，颜色编码状态，沿用统一 CSS 家族。
- `SKILL.md`：在「评价与状态」加入索引与里程碑要求，在「证据与交付」加入进度图交付要求。

**触发原因（一次真实学习会话的用户反馈）**：用户在完成一整天学习后指出——教材天然带“单元→大节→小节”的层级，学习者随时知道自己在哪；而本技能没有进度标记，导致“不知道学了多少、掌握了多少”，也无法立里程碑获得驱动力。并追加要求：**里程碑要再细分一级**，否则“要过很久才完成一个里程碑，没有成就感”——因此定为**三级**而非两级。

**与 v2.0 取舍的关系**：v2.0 取消 v1.1 的覆盖率百分比是对的（避免用一个数字假装覆盖了能力），但**没有补上替代的可感知表征**。v2.5 是补这个缺口，不是推翻 v2.0。索引报的是**计数与坐标**（`已通过 6∕共 28`），不是完成度百分比。

**仍需说明**：本补丁来自单一领域、单次会话的使用体验判断，**不足以宣称学习效果改善**，与 v2.4 之间不需重新做对照实验。

- `references/交互与状态.md` §9.1 新增「**推进顺序＝索引顺序**」：默认沿编号推进（板块 B1→B2→…）；**跨板跳跃必须留痕**（跳过哪些编号、理由、欠账清单与回补计划）。并写明后果：跳跃若不留痕，索引图会退化成“**每个板块都亮一点、却没有一条完整路径**”，学习者反而更不知道自己走在哪条路上。
- `references/各步必答问题清单.md` 第 5 步：产出追加“**每个小节末须有一道课后练习**”（每小节 1~3 题，允许分层提示；无提示独立完成可直接记“已通过”）。
- `assets/学习进度模板.md`：新增「**检验台账**」与「**跳跃记录**」两张表，进度总览增加检验台账计数。

**触发原因（同一次学习会话的追加反馈）**：
> “我建议每个小节末尾附带一个课后练习；每个单元学完进行该单元内所有内容的一次小测；每个里程碑完成后进行一次综合测试（含概念题、判断题、填空题、计算题、应用题等）。”
> 以及：“为啥目前我的学习地图点亮情况是没有规则的……目前来看是 B1-B4 都有点亮的站点，这是学习计划特意安排的吗？”

**这一条与 v2.3 直接咬合**：v2.3 曾禁止“跳过跟做与补全直接独立作答”，但没有任何机制**产出**“已练”状态——结果一次真实会话里“已练＝0”，学习者对“只被考、没被教”的抱怨因此有了量化证据。**“每小节课后练习”正是补上这个机制的那一条**：它同时是“已练”的唯一来源与“指导渐撤”的载体。

**两条边界要说清**：
1. **课后练习不是测验**——它属第 5 步，允许提示，因此**不破坏** §8.1 的教∶考配比（初阶 8∶2、中阶 6∶4、高阶 5∶5）；把它当测验用会立刻把配比推向 5∶5。
2. **题型比例是可调整默认值**，来自使用体验判断，不是学习科学结论；v2.5.1 与 v2.5 之间不需重新做对照实验。

## v2.5.2 变更（补丁级）

v2.5.2 给三级检验**补上通过分数线**，并修掉一个**会让分数线失效的口径缺陷**。

- `references/交互与状态.md` §9.4 新增「**通过分数线**」：

| 检验 | 通过线 | 提示 |
|---|---|---|
| 课后练习 | **≥ 90%** | 允许提示、跟做、补全 |
| 单元小测 | **≥ 80%** | 不给提示 |
| 里程碑综合测试 | **≥ 75%** | 不给提示、跨小节组合 |

  - **口径定为“按判分点计、不按题数计”**：小节的课后练习只有 1~3 题，若按题数算 90%，实际退化成“必须全对”（2/3＝67% 不合格、3/3＝100% 合格），中间没有档位，分数线等于失效。因此要求每题**预设判分点**，且**小节练习的判分点总数不少于 5 点**（题少就每题多设判分点）。
  - **分数是必要条件，不是充分条件**：**含关键错误一律不通过**，不论总分多高（与“不能用总体比例抵消关键错误”一致）。
  - 明确**课后练习的分数与状态是两件事**：≥90% 但用过提示 → 记“已练”；无提示独立完成且 ≥90% → 可直接记“已通过”。
  - 低于通过线**不必重刷整节**：按 §8.3 判断是本层漏洞还是先修暴露，只补相关判分点，再用同类新题复核。
- `references/各步必答问题清单.md` 第 5 步：课后练习要求增加第 ⑤ 条（通过线 ≥90%、按判分点计、判分点总数不少于 5 点）。
- `assets/学习进度模板.md`：检验台账增加「**得分（判分点）**」列，并把「判定」列改为「通过／未达线／含关键错误」。
- `references/设计规范.md` §0 **版本编号约定改为三级**（大版本／小版本／补丁），判定顺序自上而下：改整体结构、框架或逻辑 → 大版本；新增独立功能／模块 → 小版本；其余 → 补丁。
- `SKILL.md`：三级检验段补入三条通过线与“判分点不少于 5 点”。

**触发原因（同一次学习会话的追加反馈）**：
> “同意课后练习有提示，小测/综合测试没有提示。另外课后练习需要 90 分以上（或正确率 90% 以上）算通过，小测需要 80 分以上，综合测试需要 75 分以上。”
> “版本命名原则上同意你的标准，建议新增功能纳入小版本更新，更改整体结构、框架或逻辑性的东西需要按大版本更新。”

**一处必须记录的自我修正**：v2.5.1 我刚写下“课后练习每小节 1~3 题”，v2.5.2 又要加百分比通过线——**这两条放在一起是自相矛盾的**：3 题的 90% 只有 3/3 才达标，档位消失。这个缺陷不是用户提出的，**是在应用规则时发现的**，因此把口径从“按题数”改成“按判分点”，并加了“判分点总数不少于 5 点”的下限。

**边界**：三条分数线均为**可调整的默认值**，来自使用者的体验判断，**不是学习科学实验结论**；与 v2.5.1 之间不需重新做对照实验。
