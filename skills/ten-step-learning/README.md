# 十步法学习引擎（ten-step-learning）

把一个陌生专业或行业领域，拆成一套从框架理解 → 实战检验 → 口头复述的完整学习流程，产出**自包含 HTML 报告**，并支持跨会话的考官答题与费曼复述。

**版本**：v1.1

---

## 怎么用

### 最简用法

```
按十步法带我学 <领域>
```

引擎会先做**开局采集**（最多问你 5 个问题：目标领域、目标档位、你的起点、用途、是否高风险领域），然后产出**速览骨架**给你确认。

### 两阶段流程

```
开局采集 → 速览骨架（含覆盖率校验 + 样品 + 确认三问）
         → [你确认] → 精研（4 批）
         → 交付 <领域>_十步法学习报告.html
         → [可选] 考官模式答题 / 费曼复述
```

**速览骨架不是缩水版报告**，而是一页检查点。它含四块你能看懂的东西：

1. **覆盖率校验**——用外部锚定物（招聘 JD / 从业资格考纲 / 课程大纲 / 行业报告）抽出 15~25 条真实任务项，逐条标注覆盖情况，给出覆盖率数字（合格线 85%）
2. **十步骨架**——每步的一句话定位、必答问题预览、三档落点、自曝弱点
3. **样品**——第 3 + 4 步已做满精研深度，供你"试吃"
4. **确认三问**——只问你答得出的三个问题

> 设计前提：你是该领域的门外汉，**没有能力判断内容对不对**。所以确认环节不问"这个设计合不合理"，只问"覆盖没覆盖、味道对不对、天花板够不够"。

### 三档难度

| 档位 | 定位 |
|---|---|
| 入门 | 能复述机制与规则边界，能识别常见误区 |
| **专业**（默认） | 能独立完成一次标准操作与规范计算 |
| 专家 | 能在信息不全或异常情形下做出判断并说明理由 |

三档在**第 6 步统一定义一次**，全篇引用，不各步自定义。

## 为什么这么设计（v1.0 → v1.1）

v1.0 的产出实测：**判据密度只有约 5%**（定性观点句 80% + 名词清单 15%），全篇 0 真实案例、0 数据、0 反例；第 4 步给出 96/92/88/82/68 五个分数但 **0 依据、0 来源、0 算法**；第 8 步 10 道题 **100% 是概念复述题**（计算题 0 道）。

根因：v1.0 把合格线写成"**必须包含 A/B/C**"——而"包含"一句话就能满足。**形式可以被满足，内容可以在满足形式的前提下归零。**

v1.1 把每一步的合格线改成"**必须回答哪些问题 + 答到什么颗粒度**"，并加了三条硬红线：

| 红线 | 内容 |
|---|---|
| 判据密度 | 每步 ≥5 条可验证判据（第 3/4/5/6/7 步 ≥8 条）；单步纯定性观点句 ≤40% |
| 反例配额 | 每步 ≥1 条反例/失败样本/争议点；全篇 ≥5 条 |
| 证据与角标 | 每条事实性断言带内联角标 `[n]`；来源品类配额（官方 ≥40% / 教材 ≥20% / 从业者一手 ≥20% / 反向材料 ≥10%） |

其它关键变化：新增速览骨架阶段、覆盖率校验、三档难度标尺、考核题型配额（情景 ≥40% / 计算 ≥30% / 概念 ≤30%）、跨会话进度存档、高风险领域合规边界。

完整的 18 条设计决策、逐条理由与实测数据见 `references/设计规范.md`。

## 目录结构

```
SKILL.md                      主流程（唯一必需文件，先读这个）
README.md                     本文件
config.json                   可选元数据（Trae 读取；其它平台只读 frontmatter，可忽略）

references/
  深度标准.md                  判据密度、反例配额、三档定义、覆盖率、题型配额、交付自检清单
  证据规则.md                  内联角标、来源品类配额、降级分支、来源核验、合规边界
  各步必答问题清单.md            十步 × 必答问题 × 三档产出物 × 防敷衍规则（含 v1.0 反面实样）
  领域适配.md                  三种领域类型的锚定物选择与任务清单抽取
  交互与状态.md                考官/费曼纪律、进度文件格式与续接规则
  设计规范.md                  维护者用：全部设计决策与实证依据（运行时不必读取）

assets/
  骨架模板.html                 速览档骨架（覆盖率校验 + 样品 + 确认三问）
  报告模板.html                 精研档报告（统一 CSS，自包含）
  学习进度模板.md                跨会话进度文件模板
```

技能目录中只有 `SKILL.md` 是必需的。加载技能时请**保留目录内的相对路径**，`references/` 与 `assets/` 是按需读取的。

## 跨平台兼容

本技能在设计上不依赖任何特定 Agent 平台的专有能力，目标是可在 Trae / Codex / WorkBuddy 等环境中使用（**尚未逐平台验证**，见下文「开发与验证状态」）。

- **不出现专有工具名**：检索一律表述为"使用当前环境可用的联网检索能力"
- **不使用绝对路径**
- **不依赖其它 skill**（提问纪律内联在本 skill 内，不调用外部技能）
- **frontmatter 的 `name` / `description` 是各平台的通用写法**；`config.json` 仅为 Trae 的便利文件，其它平台忽略即可

### 无联网能力时的降级行为

来源降级为**检索式**（书名 + 作者 + 版次 / 关键词 + 文件编号 + 发布机构 + 年份），每条显式标注"待核实"。**禁止凭印象补链接。**

## 高风险领域

涉及**投资 / 法律 / 医疗 / 税务**时，引擎强制：

- 报告含免责声明
- **禁止**输出具体标的代码、价位、仓位数字、买卖时点
- 只允许方法论、判断维度与模拟推演，并给出**降级改写句式**

例：把"该买哪个执行价"改写成"该用哪几个维度筛选执行价"。
