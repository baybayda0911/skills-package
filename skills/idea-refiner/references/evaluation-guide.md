# 对照演练方法

供维护技能和比较效果时使用，不是每次构思讨论的步骤。用虚构或脱敏场景，评测产物保存在技能源码之外。

## 固定比较条件

- 在看模型输出前固定场景、用户材料、后续回复与评判标准；保留对照技能和待测技能的版本或文件摘要。
- 两组使用相同模型及配置、相同场景和工具权限。每个场景使用独立上下文，评测代理不接收预期答案、拟修问题或上一组结果。
- 后续回复按预先脚本交付；必须调整回复时记录差异及原因，不按推荐选项自动回答“同意”。回放已有对话时明确它是固定检查点，不冒充实际发生的轮次。
- 若可用且已授权，可通过独立评测代理执行；没有条件时开展单代理模拟，并如实注明限制。不为评测调用另付费服务、操作真实业务或安装工具。

## 最小场景集

| 场景 | 观察行为 |
| --- | --- |
| 一句话模糊构思 | 是否用具体经历打开问题，是否过早限定方案 |
| 已有充分材料 | 是否沿用约束，避免重复询问或扩张范围 |
| 上游选择未决 | 是否先处理前提，再问依赖它的下游问题 |
| 多问题后只答“可以” | 是否保留未确认决定，避免扩大同意范围 |
| 停止追问或先交草案 | 是否立即交付并标注未知，而非继续访谈 |
| 新限制影响部分决定 | 是否只重开受影响项，保留其他已确认决定 |
| 效果未知但可低成本试验 | 是否形成验证计划，区分建议阈值和已证实结果 |

可以把相邻行为组合进一个场景；不要只测擅长的题型。保留至少一项正常路径和一项异常路径。

## 证据与评分

保留实际用户输入和模型回复、轮次、使用的资源及限制。按以下维度记录通过、部分通过或未通过，并引用对应回复；有评分时先定义各档含义：

- 已有信息利用：重复提问、重开无关决定。
- 前提与决策纪律：提前问下游、把推荐或笼统同意当确认。
- 关键覆盖：遗漏会改变结果的约束、异常或验证方法。
- 交付可用性：是否满足本轮停止点，能否审阅或继续下一步。
- 回答负担：需回答的独立事项数、可避免的问题数，是否要求用户查工具能查的事实。
- 构思检验：是否比较现状或替代方法，识别可推翻假设的证据；按场景适用性评价。

提问数少、回复长、模板齐全都不单独代表更好。结构检查、单次独立代理演练、重复模型比较、真实用户任务与跨工具验证分别报告；同模型单次演练不能证明普遍优于对照技能。

发现失败后做有证据的局部修改，使用新上下文重放受影响场景；报告初次结果和复测结果，不覆盖初次失败记录。
