# 产品与体验补充

适用于工具、服务、页面、课程使用体验和活动参与流程。只展开会影响当前方案的项目。

## 优先澄清

- 谁在什么场景遇到什么麻烦，现有解决方式哪里不够好。
- 维持现状或使用现成办法能否满足目标；哪些具体经历支持“需要新方案”。
- 首次接触时能否快速知道“这是什么、下一步做什么”。
- 一个完整的最小使用流程是什么；哪些功能先不做。
- 参与者之间如何交接，谁负责后续结果。
- 怎么取消、返回、撤销；哪些操作需要防误触。
- 手机、线下、网络不稳定或时间有限是否影响使用。
- 需要保存什么信息、保存多久、谁能看；能否少收集。

## 先描述体验

界面类任务先给文字版原型：

```text
入口：用户打开后首先看见……
主体：上方显示……，中间提供……，主要按钮位于……
操作：点击后……，完成时显示……
退路：取消或返回会……，重要操作先确认……
```

无界面服务或活动使用“到达 → 准备 → 核心体验 → 结果 → 退出或后续”的文字流程，不强求页面和按钮。

## 方案补充字段

- 核心场景、完整使用路径和第一版边界。
- 正常、空内容、失败、等待和取消时的反馈。
- 易误操作处与保护办法。
- 成功标准和验证方式，不凭空承诺参与量或使用率。
- 核心需求假设、可能推翻它的行为证据、试用范围与停止条件；先检验需要，再扩大功能。
- 加分项仅列为候选，例如进度提示；不要默认添加积分和徽章。
