# Idea Refiner：通用完善构思

帮助你把“有个想法，但还没想清楚”逐步整理成目标明确、范围合理、可以执行和检验的方案。

它要求 AI 沿用已有信息，按问题的前提关系澄清关键选择，并检查现状、替代方法和可能推翻构思的证据，再形成方案。需要通过实际试用才能回答的问题，会转为小规模验证计划。是否实施，由你的确认与授权决定。

本文件供使用者阅读；[SKILL.md](SKILL.md) 是 AI 加载技能时的工作说明。

## 适合什么时候用

- 有一个模糊想法，希望有人帮你理清目标与第一步。
- 准备做产品、写程序、整理工作流程，但关键选择还没确定。
- 策划文章、课程、研究或活动，希望先明确结构和完成标准。
- 改进个人工作或学习安排，需要把愿望变成具体方案。
- 继续完善已有方案，希望保留之前的决定而不是从头讨论。

目标已明确、只需直接执行的任务，简单问答或单纯文字润色，不需要专门使用这个技能。

## 怎么开始

先按所用工具的说明加载本技能。需要安装时，安装整个 `idea-refiner/` 目录，而不只是一个 `SKILL.md`，以保留参考模板。

支持 `$技能名` 调用的环境可以这样说：

```text
请使用 $idea-refiner 完善我的构思：
我想组织一次读书交流活动，只有两周准备时间。
先帮我形成方案，不开始执行。
```

工具能读取本地文件、但不支持上述调用方式时，可以明确要求：

```text
请读取 skills/idea-refiner/SKILL.md，
再按其中要求读取与任务相关的参考材料，帮助我完善下面的想法：……
本次只讨论并形成方案。
```

这里的路径相对于技能集合仓库根目录。在其他目录中工作时，请提供实际可访问的位置。工具不能读取文件时，需要另行提供技能正文及必要材料，单独给出路径不够。

没有项目文件夹，也可以开展构思讨论；不依赖某个特定插件。不过自动查资料、写文件和实施的能力，取决于所用助手是否具备相应工具。

## 讨论会怎样推进

| 阶段 | AI 应该做什么 | 你需要做什么 |
| --- | --- | --- |
| 理解构思 | 沿用已有信息，概括目标、对象、理想结果和范围 | 补充或纠正关键理解 |
| 逐轮澄清 | 通常每轮问 1 至 3 个关键问题；按用途问经历、数值或真实选项，并检查关键假设 | 描述经历、补充限制、选择或允许代选 |
| 形成方案 | 整理范围、流程、异常、完成标准；效果未知时给验证计划 | 审阅草案，需要时确认范围 |
| 按授权落地 | 仅在方案确认且获得实施授权后执行，并说明验证结果 | 明确是否实施及允许的动作 |

问题围绕目标、对象、入口、过程、结果和异常展开，按任务需要增减。涉及界面时，先描述布局和点击后的变化；非软件任务则描述参与者、步骤和产出。

AI 的推荐不是你的决定，未回答也不代表同意。已有明确确认时应沿用，只有新信息影响的部分需要重新讨论。

## 会得到什么

| 方案大小 | 典型产出 |
| --- | --- |
| 轻量 | 目标、最小方案、边界、待决项和下一步，可直接在对话中交付 |
| 标准 | 方案摘要、决策记录、正常与异常流程、完成标准 |
| 完整 | 标准版加职责、资源、依赖、阶段计划与证据记录 |

不是每次都需要建文件或填完整模板。需要文件时，保存位置应遵守你的要求和当前环境规则。

方案会区分已查证事实、已确认决定、推荐、暂定假设和未知项。未知进一步区分：权限、输入等阻塞项限制受影响执行；需求、效果等验证项可以通过小规模试验检验。验证计划包含方法、指标、建议阈值、期限与停止条件；计划完成不代表效果已证实，也不自动授权试验。

AI 会优先问答案能实质改变方案的问题，小细节可以代拟并标注。如果连续两轮没有实质变化，应检查是否可以交付草案；这不是强制轮数，关键阻塞仍须说明。信息已经充分时可以直接交付。

## 如何控制节奏

你可以随时调整讨论方式：

```text
先别继续提问，按目前信息给我一份草案，标明假设和待确认项。
```

```text
这轮只解决核心流程，其他想法放到后续候选。
```

```text
继续上次的方案，沿用已确认的决定，只讨论受新限制影响的部分。
```

准备实施时，应明确对应的方案版本、范围和允许动作。例如：

```text
我确认这份方案和本轮范围。请按方案修改本地文件并验证，
不要提交、推送、安装或对外发布。
```

只要方案，就在交付方案后停止。允许本地实施，不自动代表允许删除资料、购买服务、发消息、部署或建立定时任务。

## 限制与验证

- 验证应分别报告入口和引用检查、独立代理对话演练、真实任务效果与跨工具兼容性；演练方法见上方参考材料。具体完成情况以实际验证记录为准，不以文件已发布推断。
- 2026-10-12 已完成入口、展示配置及相对引用检查，并用当前助手默认配置的独立代理，与本机 grilling 1.3.1 完成一次六场景、34 条助手回复的多轮脚本对照演练。没有另设模型覆盖；具体模型字符串和采样参数未由评测接口报告。实际回复与评审保存在仓库外的管理资料中。
- 根据初测结果局部补充了开发模板的试跑前提、基线比较与继续/退回条件，随后用新上下文和相同票据场景输入完成三条回复复测。原始结果保留，局部复测不替代全套比较。
- 复测仍发现输入读取边界的缺口，因此明确了文件整理场景同时读取开发补充的路径；随后完成一个新上下文的最终草案固定回放检查点。该回复注明输入范围、试跑授权、同批样本比较和成本抵消时缩小方案；这是单检查点观察，不是新一轮全套评分或真实试跑。
- 本次只覆盖虚构场景的方案讨论，不含真实业务执行、重复运行稳定性、全局安装或跨工具兼容验证。中途服务容量错误有单独记录；保留第一个完整回复，不按答案质量挑选重试。
- 文件检查通过，不等于实际对话或真实工作效果已验证；效果取决于模型、材料和可用工具。
- 研究计划不等于研究结论，文件存在不等于真实运行成功，用户确认也不能替代专业复核。
- 私人构思不应默认写入公开仓库；记录应使用必要摘要、虚构或脱敏例子，避免复制凭据和完整私人访谈。
- 医疗、法律、财务等高风险事项需要适当的专业判断和复核，技能不提供效果保证。
